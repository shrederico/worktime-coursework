# Проверки платформы

## Приложение и данные

`python3 scripts/verify_platform.py` проверяет пять сервисов Compose, выполняет
15 тестов с PostgreSQL, создаёт резервную копию при остановленной записи,
восстанавливает её в отдельную временную базу и сравнивает содержимое пользователей,
задач и записей времени. После пересоздания контейнера БД с прежним томом сравнение
повторяется. В конце приложение возвращается в работу.

Результат каждого этапа и время запуска записываются в
[verification-results.json](verification-results.json). Статус `passed` относится
к указанному запуску. Копии находятся в локальном каталоге `backups/` и не входят в Git.

Автоматические тесты описаны в [tracker/tests.py](../tracker/tests.py).
Проверки с SQLite подходят для прикладной логики, но не подтверждают работу
блокировок PostgreSQL и контейнерной инфраструктуры.

## Кластеры и доставка

- [kubernetes-results.json](kubernetes-results.json): готовность трёх узлов,
  две реплики на разных worker, замена удалённого Pod и запрос через Nginx к БД.
- [local-pipeline-results.json](local-pipeline-results.json): локальная сборка,
  тесты и последовательное обновление Swarm.
- [github-results.json](github-results.json): успешные задания `test`, `build`,
  `deploy`, две реплики и HTTP-проверка для указанного коммита.
- [swarm-results.json](swarm-results.json): снимки состояния учебного Swarm.
  В снимке после остановки присутствуют `Pending` и `Failed`; одного поля
  `status: passed` недостаточно для подтверждения завершённого восстановления
  обеих реплик. Для проверки работающей версии используется отдельный протокол доставки.

## Границы результатов

Протоколы отражают состояние в момент проверки. Они не являются непрерывным
наблюдением за сервисами. Учебные узлы размещены на одном Mac, база не реплицируется.
Нагрузочные испытания и измерение гарантированного времени восстановления не проводились.
