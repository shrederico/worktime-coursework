# GitHub и автоматическое обновление

Закрытый репозиторий: https://github.com/shrederico/worktime-coursework.
Runner worktime-mac зарегистрирован только в этом репозитории, метки macOS,
ARM64 и worktime. Файлы runner находятся в .lab/runner и исключены из Git.
Системная служба и автоматический запуск при входе в macOS не устанавливались.

При push в main запускаются:

1. Тесты с PostgreSQL в GitHub-hosted Linux runner.
2. Сборка образа ARM64/AMD64 и публикация в GHCR с тегом SHA коммита.
3. Собственный Mac runner скачивает образ и загружает его на manager и worker
   учебного Swarm. Применяет миграции и последовательно обновляет две реплики.
4. Проверка версии обеих реплик, результата обновления и HTTP health.

Для pull request выполняются только тесты на GitHub-hosted runner. Развёртывание
допускается только из main при DEPLOY_ENABLED=true; запуски идут последовательно.
WORKTIME_RUNTIME_DIR указывает на локальную папку проекта. .env, базы и резервные
копии не отправляются в GitHub. Вход GHCR использует временный GITHUB_TOKEN задания.

Для доставки обновления Mac должен быть включён, Docker Desktop запущен,
учебный Swarm работать, runner находиться онлайн. Если после перезапуска Mac runner
offline, запустить задачу VS Code «GitHub: включить runner после перезапуска Mac».
Не запускать вторую копию runner, если он уже слушает задания.

Основная Compose-платформа на порту 8080 при доставке обновления не меняется.
Обновляется только Swarm на порту 8081. Kubernetes пока демонстрируется отдельно.
Учебная модель миграций предполагает совместимость схемы с предыдущей версией.
