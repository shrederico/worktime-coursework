# Worktime

Учебная платформа для учёта рабочих часов и задач сотрудников, разработанная
в рамках курсовой работы «Настройка и администрирование платформы для
автоматизации учёта рабочих часов и задач сотрудников».

Руководитель создаёт и назначает задачи, сотрудник изменяет статус и записывает
затраченное время. Отчёт позволяет выбрать период и выгрузить записи в CSV.
Руководителю доступны данные команды, сотруднику — собственные задачи и записи.
Пользователи создаются администратором через `/admin/`.

## Архитектура

| Сервис | Назначение |
| --- | --- |
| Nginx (`proxy`) | Приём HTTP-запросов и передача их приложению |
| Django / Gunicorn (`app`) | Задачи, рабочее время, отчёты и разграничение доступа |
| PostgreSQL (`db`) | Хранение пользователей, задач и записей времени |
| Prometheus | Сбор метрик приложения |
| Grafana | Отображение состояния платформы и показателей учёта |

Пользовательский запрос проходит по цепочке Nginx → Django → PostgreSQL.
Prometheus собирает показатели через `/metrics/`, Grafana получает их из Prometheus.
В Compose настроены сети `web`, `data`, `monitoring` и именованные тома.
Порт базы данных не публикуется; внешние порты Compose привязаны к `127.0.0.1`.
Nginx запрещает внешний доступ к `/metrics/`.

## Запуск

Требуются Git, Python 3 и запущенный Docker Desktop с Docker Compose.
Команды выполняются в терминале из каталога проекта.

```sh
git clone https://github.com/shrederico/worktime-coursework.git
cd worktime-coursework
sh scripts/start.sh
```

Скрипт создаёт `.env`, собирает образ, применяет миграции, добавляет
демонстрационные данные и запускает пять сервисов. Существующий `.env`
и пароли пользователей при повторном запуске сохраняются.

- Приложение: http://localhost:8080.
- Grafana: http://localhost:3000, панель «Worktime — состояние платформы».
- Руководитель и администратор: `manager`; сотрудники: `anna`, `ivan`.
- Начальный пароль пользователей: значение `DEMO_PASSWORD` в локальном `.env`.
- Grafana: логин `admin`, пароль — значение `GRAFANA_PASSWORD` в `.env`.

Демонстрационные данные вымышленные. `.env`, базы, резервные копии и файлы
локальных кластеров исключены из Git.

## Управление платформой

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose stop
docker compose up -d --wait
```

`stop` останавливает сервисы, сохраняя данные. `up -d --wait` запускает их снова.
Удаление томов приводит к удалению хранящихся в них данных.

## Проверки и резервное копирование

Тесты приложения выполняются в отдельной тестовой базе:

```sh
docker compose exec app python manage.py test tracker
```

В проекте 15 тестов: вход и права доступа, создание и статусы задач, запись часов,
ограничения времени и дат, фильтр отчёта, CSV, CSRF, адреса состояния и метрик.

Создание резервной копии PostgreSQL:

```sh
sh scripts/backup.sh
```

Копия сохраняется в `backups/`. Полный сценарий проверки:

```sh
python3 scripts/verify_platform.py
```

Он выполняет тесты с PostgreSQL, временно останавливает приложение, создаёт копию,
восстанавливает её в отдельную базу и сравнивает пользователей, задачи и записи
времени. Затем проверяет сохранность данных после пересоздания контейнера БД
с прежним томом и возвращает приложение в работу. На время проверки сайт недоступен.
Результаты и границы проверок описаны в [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Swarm, Kubernetes и CI/CD

| Стенд | Организация | Адрес приложения |
| --- | --- | --- |
| Compose | Пять сервисов на Docker Desktop | http://localhost:8080 |
| Swarm | Manager и worker, две реплики приложения | http://localhost:8081 |
| Kubernetes / kind | Control-plane и два worker, две реплики приложения | http://localhost:8082 |

Стенды используют отдельные базы данных. Адрес Kubernetes доступен при работающем
перенаправлении порта. Команды приведены в [docs/CLUSTERS.md](docs/CLUSTERS.md).

GitHub Actions выполняет тесты с PostgreSQL, собирает образ ARM64/AMD64,
публикует его в GHCR с тегом SHA коммита и через runner на Mac обновляет Swarm.
Развёртывание выполняется из `main` при `DEPLOY_ENABLED=true` и доступном runner.
Для pull request выполняются тесты. Compose и Kubernetes этим процессом не обновляются.
Настройка описана в [docs/GITHUB.md](docs/GITHUB.md).

Успешное выполнение заданий `test`, `build`, `deploy` зафиксировано в
[запуске GitHub Actions](https://github.com/shrederico/worktime-coursework/actions/runs/41310770497)
для коммита `7642a8e2db39a27886c28c5db2c8665fd9947da0`.
Протокол: [docs/github-results.json](docs/github-results.json).

## Структура репозитория

- `tracker/` — модели, формы, обработчики запросов и тесты.
- `templates/`, `static/` — интерфейс приложения.
- `config/` — настройки Django и маршруты.
- `infra/` — Nginx, мониторинг, Swarm и Kubernetes.
- `scripts/` — запуск, резервное копирование, развёртывание и проверки.
- `docs/` — эксплуатационная документация и протоколы проверок.
- `.github/workflows/ci.yml` — процесс CI/CD.

## Ограничения

Все кластерные узлы работают на одном физическом Mac. В каждом стенде PostgreSQL
имеет один экземпляр без репликации. Две реплики приложения не обеспечивают
отказоустойчивость при отказе Mac или базы данных. В Kubernetes история мониторинга
временная, база использует PVC. Нагрузочные испытания не проводились.

В пользовательском интерфейсе нет редактирования и удаления записанных часов,
расчёта зарплаты и согласования табелей. Платформа предназначена для учебной
эксплуатации в локальной среде.
