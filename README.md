# Worktime

Учебная платформа для курсовой по настройке и администрированию сервисного ПО.
Руководитель создаёт задачи и назначает исполнителей. Сотрудник меняет статус
своей задачи и записывает рабочие часы. Отчёт показывает записи за период и
позволяет выгрузить CSV. Данные в демонстрации вымышленные.

## Быстрый запуск на Mac

1. Откройте Docker Desktop и дождитесь его запуска.
2. Откройте эту папку в VS Code (именно `worktime`).
3. В терминале VS Code выполните `sh scripts/start.sh`.
4. Откройте http://localhost:8080.

В VS Code также доступны команды меню **Терминал → Выполнить задачу**.

Учётные записи: `manager` — руководитель и администратор; `anna`, `ivan` —
сотрудники. Пароль для всех трёх создан при первом запуске и записан в `.env`
в строке `DEMO_PASSWORD`. Пароль Grafana — `GRAFANA_PASSWORD`, логин — `admin`.
Файл `.env` не публикуется в Git. Повторный запуск не меняет существующие пароли
и не удаляет данные. Если пароль учётной записи изменён, `seed_demo` его не сбрасывает.

Мониторинг: http://localhost:3000 → Dashboards → Worktime — состояние платформы.

Остановка без потери данных: `docker compose stop`.
Повторное включение: `docker compose up -d --wait`.
Просмотр состояния: `docker compose ps`.
Журналы приложения: `docker compose logs --tail=100 app`.

## Пять сервисов

| Сервис | Что делает |
| --- | --- |
| proxy / Nginx | Принимает запросы браузера и передаёт их приложению |
| app / Django и Gunicorn | Проверяет вход, обрабатывает задачи, часы и отчёты |
| db / PostgreSQL | Постоянно хранит пользователей, задачи и записи времени |
| prometheus | Раз в 15 секунд собирает доступность приложения и показатели |
| grafana | Показывает доступность, часы и количество задач на панели |

Путь запроса: браузер → Nginx → Django → PostgreSQL.
Путь мониторинга: Prometheus → Django `/metrics/`; Grafana → Prometheus.
База не публикует порт на Mac. Внешние порты Compose привязаны к `127.0.0.1`.
Nginx закрывает `/metrics/` от внешнего доступа. Между сервисами используются
имена `app`, `db`, `prometheus`, а не изменяющиеся IP-адреса контейнеров.

## Что можно показать

1. Войти как manager, создать задачу и назначить anna.
2. Выйти и войти как anna: видны только её задачи.
3. Перевести новую задачу в статус «В работе» и записать 1,5 часа.
4. Открыть отчёт, выбрать даты и скачать CSV.
5. Войти как manager: в отчёте видны записи всей команды.
6. Открыть Grafana: после следующего сбора метрик обновится общее время.
7. Перезапустить app и убедиться, что запись осталась в базе.

Администратор создаёт пользователей через `/admin/`. Для обычного сотрудника
флаги «Статус персонала» и «Статус суперпользователя» должны быть выключены.
Руководитель имеет `is_staff`; полный доступ к админке имеет демонстрационный
manager с `is_superuser`. Изменение назначенного исполнителя доступно администратору.
Редактирование/удаление записанных часов в интерфейсе не реализовано: это
сознательная граница первой версии, а не полноценная система согласования табелей.

## Код

- `tracker/models.py` — две сущности: задача и запись времени;
- `tracker/forms.py` — поля форм и проверка данных;
- `tracker/views.py` — обработка запросов и права доступа;
- `templates/`, `static/` — страницы и оформление, без React и сборщика JavaScript;
- `config/` — настройки Django и адреса страниц;
- `infra/` — Nginx, мониторинг, Swarm и Kubernetes;
- `scripts/` — запуск, резервная копия и развёртывание;
- `.github/workflows/ci.yml` — подготовленный процесс CI/CD.

## Проверки

`docker compose exec app python manage.py test tracker`

Тесты используют отдельную тестовую базу и не изменяют рабочие записи. Проверяются
роли, доступ к чужим задачам, создание и статус задач, диапазон часов, суточный
лимит, будущие даты, фильтр отчёта, CSV, CSRF и технические адреса.

Без Docker можно выполнить `sh scripts/local.sh` и открыть http://localhost:8000.
В этом режиме используется отдельная SQLite-база `local.sqlite3`; она не является
базой контейнерного стенда. Для курсовой демонстрируется PostgreSQL в Docker.

## Резервная копия

Полная проверка: `python3 scripts/verify_platform.py`. Скрипт запускает тесты,
временно останавливает приложение, создаёт резервную копию, восстанавливает её
в отдельную базу и сравнивает всё содержимое пользователей, задач и записей времени.
Затем пересоздаёт контейнер PostgreSQL с тем же томом и повторяет сравнение.
В конце возвращает приложение в работу, в том числе при ошибке промежуточного шага.
Результаты записываются в `docs/verification-results.json`; статус `passed` появляется
только после реального успешного выполнения. Во время проверки сайт временно недоступен.

`sh scripts/backup.sh` сохраняет SQL в `backups/`.
`bash scripts/verify_backup.sh backups/имя-файла.sql` восстанавливает копию
в отдельную временную базу, показывает количество задач, записей и сумму часов,
затем удаляет только эту временную базу. Сравните числа с состоянием на момент
создания копии. Рабочая база не изменяется. Том обеспечивает сохранность при пересоздании контейнера,
а резервная копия позволяет восстановить данные отдельно от тома.

## Следующие этапы

Swarm и Kubernetes развёрнуты и проверены на отдельных логических узлах.
Локальная сборка, тесты и доставка обновления в Swarm проверены. GitHub Actions
подготовлен, но удалённый запуск требует репозитория и runner. Протоколы — в
`docs/CLUSTER_VERIFICATION.md`. Наличие workflow не означает выполненный удалённый CI/CD.
Условия и команды описаны в `docs/CLUSTERS.md`; фактические проверки — в
`docs/VERIFICATION.md`. Отчёт Word, титульные листы и презентация не создаются
на данном этапе.
